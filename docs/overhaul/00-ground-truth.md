## 6. Persistence

- `Documents/packs.json` **embeds base64** `stickerData`/`previewData` (~33% inflation) — confirmed. Re-encoded in full on **every** mutation, synchronously on the main actor (`PackStore.save()` `:181-184` uses `try?`, swallowing errors).
- `load()` (`:176-179`) also `try?` → a corrupt file silently resets to `[]`.
- Originals in `Documents/Sources/<uuid>.<ext>`; `removePack` (`:143-146`) does **not** delete them → leak.
- `UserDefaults` `stickreate.*` via `SettingsStore`.

## 11. External constraints & discrepancies

### 11.1 Liquid Glass / HIG (Apple, iOS 26)
- Glass is the **control/navigation layer only** (tab bars, toolbars, sheets, menus, ≤1 prominent control per screen). Never in content. Never glass-on-glass. `.regular`/`.clear` must not mix. Tint selectively.
  - https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass
  - https://developer.apple.com/videos/play/wwdc2025/219/
- Primary API present but **unused**: `glassEffect(_:in:)` (default `.regular`, default shape `Capsule`), `GlassEffectContainer` (shared sampling + morphing via `glassEffectID(_:in:)`), `ToolbarSpacer`, `scrollEdgeEffectStyle(_:for:)`.
  - https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:)
  - https://developer.apple.com/documentation/swiftui/glasseffectcontainer
- Sheets adopt glass; `presentationDetents` for medium/large.

### 11.2 Accessibility
- Dynamic Type to largest AX sizes; reflow via `dynamicTypeSize` + `AnyLayout`.
- Target the audit types: `.contrast`, `.hitRegion` (44×44), `.sufficientElementDescription`, `.dynamicType`, `.textClipped`, `.trait`. `XCUIApplication.performAccessibilityAudit()` fails the test on issues.
  - https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app

### 11.3 App Review
- **4.2 Minimum Functionality** — *highest risk*: WhatsApp itself warns the official sticker sample "will not be accepted by Apple"; a sticker-only wrapper is vulnerable. The app must show real creation/editing value. https://developer.apple.com/app-store/review/guidelines/#minimum-functionality
- **5.2.1(c)** — no third-party brand/logo in the app name or icon; referential "works with WhatsApp stickers" wording only, no endorsement implication. https://developer.apple.com/app-store/review/guidelines/#intellectual-property
- **2.1 completeness**, **1.2 UGC** (on-device, no server ⇒ moderation not required), **5.1.1 privacy** (permissions in context; privacy policy in-app + App Store Connect).

### 11.4 Privacy Manifest
- Required filename `PrivacyInfo.xcprivacy`. App that collects nothing: `NSPrivacyTracking=false`, empty domains/collected types, plus only the required-reason APIs actually used.
- Confirmed current codes: UserDefaults **CA92.1**, FileTimestamp **C617.1**, DiskSpace **E174.1**, SystemBootTime **35F9.1**.
- **SDWebImage is on Apple's required-SDK list** (ships its own manifest). ZIPFoundation ships its own manifest (`0A2A.1`) and is not on the list. `libwebp-Xcode` is a source package with no manifest — verify it needs none. https://developer.apple.com/support/third-party-SDK-requirements/

### 11.5 Export compliance
- `ITSAppUsesNonExemptEncryption=false` is correct: ZIP is compression, WebP is encoding — neither is non-exempt encryption. (Already set.)

### 11.6 WhatsApp spec (confirmed vs repo `Limits.swift`)
- 512×512; static ≤100 KB; animated ≤500 KB; pack 3–30; **never mixed**; animation ≤10 s; frame ≥8 ms; tray 96×96 PNG/WebP ≤50 KB; ≤3 emojis; accessibility text ≤125/≤255 chars.
  - https://github.com/WhatsApp/stickers/blob/main/iOS/WAStickersThirdParty/Limits.swift
- Import: pasteboard type `net.whatsapp.third-party.sticker-pack`, `.localOnly`, 60 s expiry, then `whatsapp://stickerPack`. https://github.com/WhatsApp/stickers/blob/main/iOS/WAStickersThirdParty/Interoperability.swift
- **error 1000**: unofficial catch-all; reported causes = invalid WebP/tray, or a bundle id still containing `WA.WAStickersThirdParty`; community workaround = delay (≈1 s) between pasteboard and open. No official timing. https://github.com/WhatsApp/stickers/issues/127
- **White 8-px border is a WhatsApp *recommendation* only**, not automatic — the app's "never add a border" rule is compatible.

### 11.7 Tooling
- `macos-15` includes Xcode 26.x but **defaults to Xcode 16.4** (CI already `xcode-select`s the newest). `macos-26` is now GA and may be preferable.
- AltStore/SideStore source JSON fields: `name`, `identifier`, `sourceURL`, `apps[]` each with `name`, `bundleIdentifier`, `developerName`, `subtitle`, `localizedDescription`, `iconURL`, `tintColor`, `versions[]` (`version`, `buildVersion`, `date`, `downloadURL`, `size`, `minOSVersion`). https://faq.altstore.io/developers/make-a-source

## 12. Discrepancies / decisions needed

1. **`.wasticker` semantics.** Docs call it a ZIP we own; WhatsApp's official `.wasticker` is a **JSON** metadata file. Risk of confusion with a real WhatsApp format. Options: keep our ZIP but rename the extension (own the UTI), or keep as-is and document clearly. → resolve in Phase 7 (UTI) / Phase 4.
2. **Version drift.** `project.yml` = `0.3.0`; docs say v0.19.0; tags drive releases. → normalize in Phase 8.
3. **Accent coral/pink on every glass control** contradicts Apple's "tint selectively". → Phase 3 validates contrast and reserves tint for primary actions.
4. **`.wasticker` and 4.2 risk** both flagged — the app needs demonstrable originality beyond "sticker export".
5. **No localization** at all — Phase 3 adds String Catalog EN + es-AR.
